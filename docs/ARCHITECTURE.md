# Архитектура: сессионный экшен-тайкун

Одна открытая карта без фаз и безопасных зон. Ресторан — физическая
крепость. Деньги появляются только в кассах и выпадают с убитых владельцев.

## 1. Карта систем

Сервер авторитарен: клиент присылает намерения, сервер проверяет и считает.

| Сервис | Отвечает за | Зависит от |
|---|---|---|
| `NetService` | создание Remotes, лимиты частоты, проверка аргументов, анти-чит | — |
| `DataService` | сохранения, блокировка сессии, миграции | Net |
| `PlotService` | участки, владельцы, модели уровней, улучшение, «база под атакой» | Data, Net |
| `ClassService` | класс игрока, маскировка разведчика, смена класса | Data, Net, Plot |
| `CashRegisterService` | касса: выручка, сбор владельцем, взлом | Plot, Class, Data, Net |
| `RestaurantService` | доход, остановка при разрушении, ремонт | CashRegister, Plot, Data, Net |
| `GuardAIService` | обнаружение и атака охраной и турелями | Plot, Class, Net |
| `WeaponService` | выдача оружия, стрельба, урон, разрушение, блик прицела | Class, Combat, Data, GuardAI, Net, Plot |
| `CombatService` | кто кого ранил, выпадение денег при гибели, штраф за выход из боя | Data, Net |
| `LeaderstatsService` | таблица игроков (витрина) | Data |

Зависимости идут в одну сторону, циклов нет. Сервисы ниже по таблице
узнают о событиях выше через сигналы (`PlotService.RestaurantBuilt`,
`DataService.Loaded` и т. д.) и через `onRestaurantBuilt` / `onLoaded`.
Эти функции вызывают обработчик и для уже существующих объектов, поэтому
порядок запуска сервисов не важен.

Клиент: `StateController` (копия данных), `NotificationController`,
`RegisterController` (подсказки кассы), `EffectsController` (трассеры),
`WeaponController` (выстрелы, приближение прицела), `SettingsController`.

**В планах** (их места в архитектуре уже заложены):

| Сервис | Что делает | Точка подключения |
|---|---|---|
| `AbilityService` | способности классов: подавление, щит, метки разведчика, заряды подрывника | `Config/Classes`, `CombatService:recordDamage` |
| `ShopService` | покупка оружия и улучшений за Cash | `WeaponService:giveWeapon`, `Config/Weapons.Price` |
| `DefenseService` | наём и увольнение охраны в слоты | `Restaurant.Defense` в данных, теги `DefenseSlot` |
| `CustomerService` | NPC-клиенты, повара, официанты (визуальный слой) | `CashRegisterService:deposit` |
| `MovementService` | серверная проверка скорости и телепортов | — |

## 2. Данные

### DataStore

Одна запись на игрока: хранилище `PlayerData_v1`, ключ `Player_<UserId>`,
с блокировкой сессии (см. `DataService`).

```
PlayerData (Version = 2)
├─ Cash: number                      кошелёк
├─ Class: string                     ключ из Config/Classes
├─ Restaurant
│  ├─ Tier: number                   1..4
│  ├─ NeedsRepair: boolean           сломан (переживает перезаход)
│  └─ Defense: { [SlotId]: DefenderType }
├─ Equipment
│  └─ Weapons: { [WeaponId]: level }
├─ Settings { MusicVolume, ShowTips }
└─ Stats { FirstJoin, LastJoin, Logins, Robberies, TimesRobbed, CashStolen }
```

Глобальные таблицы рекордов (самый богатый, лучший вор) — отдельные
`OrderedDataStore`. Обновлять их раз в несколько минут, а не при каждом изменении.

### Состояние сессии (только в памяти сервера)

| Что | Где | Почему не сохраняется |
|---|---|---|
| Деньги в кассе | `CashRegisterService` | Иначе владелец выходил бы из игры в начале штурма и «уносил» кассу. Забирать выручку вовремя — часть игры |
| Убитый персонал, сломанная мебель | `RestaurantService` | Сохраняется только итог: флаг `NeedsRepair` |
| Тревога охраны | `GuardAIService` | Бой — событие сессии |
| Раскрытие и взлом разведчика | `ClassService`, `CashRegisterService` | То же |
| Номер участка | `PlotService` | Участок выдаётся заново при каждом входе |

## 3. Сеть

| Событие | Направление | Аргументы | Обработчик |
|---|---|---|---|
| `DataSync` | → клиент | `"Full", data` / `"Set", key, value` | StateController |
| `Notify` | → клиент | `text` | NotificationController |
| `HackState` | → клиент | `"Started", endsAt` / `"Ended", success` | RegisterController |
| `ShotFired` | → клиент (unreliable) | `origin, impact` | EffectsController |
| `ChangeSetting` | → сервер | `name, value` | SettingsService |
| `SelectClass` | → сервер | `classId` | ClassService |
| `UpgradeRestaurant` | → сервер | — | PlotService |
| `RepairRestaurant` | → сервер | — | RestaurantService |
| `Fire` | → сервер | `direction` | WeaponService |

Касса работает через `ProximityPrompt`: «Забрать выручку» (E) и «Взломать» (F).
`Triggered` для сервера — такой же ввод клиента: лимит частоты, проверка роли,
серверная проверка расстояния, серверный таймер.

## 4. Сцена: участки и модели уровней

### Участок (в Workspace, не меняется)

```
Workspace
└─ Plots (Folder)
   └─ Plot1 (Model, тег "Plot")
      ├─ Origin     (Part)  пивот для модели ресторана
      ├─ Territory  (Part)  объём территории (невидимый, CanQuery = false)
      ├─ Spawn      (SpawnLocation, необязательно)
      ├─ Defense    (Folder) нанятая охрана (создаётся сам)
      └─ Restaurant (Model)  текущий уровень — ставит PlotService
```

### Шаблоны уровней (в ServerStorage, а не в ReplicatedStorage)

```
ServerStorage
└─ Restaurants
   ├─ Tier1 (Model)
   │  ├─ Structure       стены, двери, окна (атрибуты: SeeThrough, ShootThrough, MaxHealth)
   │  ├─ Furniture       столы, плиты           — тег "Furniture"
   │  ├─ Staff           повара, официанты      — тег "Staff" на модели с Humanoid
   │  ├─ CashRegister    касса                  — тег "CashRegister"
   │  ├─ CustomerSpawns  точки под навесом      — тег "CustomerSpawn"
   │  ├─ DefenseSlots    слоты охраны           — тег "DefenseSlot", атрибуты SlotId, SlotKind
   │  └─ Guards          охрана «из коробки»    — тег "Guard"/"Turret", атрибут DefenderType
   ├─ Tier2 …
   ├─ Tier3 …
   └─ Tier4 …
└─ Weapons
   └─ Pistol, Rifle, Sniper (Tool с Handle, атрибут WeaponId)
```

**Почему ServerStorage.** Всё содержимое ReplicatedStorage скачивается каждому
клиенту при входе. Это четыре полных здания на каждого игрока, и вдобавок
читеры спокойно изучают планировку (слоты охраны, укрытия). В ServerStorage
шаблоны есть только на сервере, а клиент получает копию, когда она встаёт
на карту. В ReplicatedStorage стоит класть только лёгкие превью для окна
улучшения (`ReplicatedStorage/Previews`).

**Правила бесшовной замены:**

1. **Общий пивот.** У каждого шаблона `WorldPivot` (или `PrimaryPart`) стоит
   в точке, которая совпадает с `Plot.Origin`. Замена — это
   `clone:PivotTo(Origin.CFrame)`. Все уровни строятся вокруг одной точки
   с одинаковым входом. Поэтому дорожки, навесы и точки NPC не съезжают.
2. **Сначала строим, потом сносим, без yield между ними.** `PlotService`
   ставит новую модель и удаляет старую в одном кадре, пустого участка никто
   не увидит. Сигнал `RestaurantBuilt` сообщает кассе, экономике и охране,
   что модель новая.
3. **Стабильные `SlotId`.** Слот у двери называется `Door1` на всех уровнях,
   где он есть. Тогда нанятая охрана из `Restaurant.Defense` переезжает
   на новый уровень сама. Новые слоты (`Roof1` на Tier 3) просто добавляются.
4. **Состояние живёт не в модели.** Деньги кассы хранятся по участку, а не
   по объекту кассы, поэтому переживают и улучшение, и ремонт.
5. **Футпринт растёт, а не меняется.** Каждый следующий уровень покрывает
   площадь предыдущего. Иначе игроки внутри окажутся в новых стенах. Если
   это неизбежно, перед заменой переместите персонажей из `GetBoundingBox()`
   новой модели к `Spawn`.
6. **Стриминг.** При `StreamingEnabled` ставьте моделям уровней
   `ModelStreamingMode = Atomic`: здание приходит клиенту целиком, без дыр.
7. **Под атакой не меняем.** Улучшение и ремонт перестраивают модель целиком,
   а значит, чинят стены. Поэтому оба действия запрещены, пока
   `PlotService:isInCombat`.

Материалы по уровням (атрибуты деталей `Structure`; `MaxHealth` — разрушается пулями):

| Уровень | Стены | Окна |
|---|---|---|
| Tier 1 | доски: `ShootThrough`, `MaxHealth` 120 | проёмы без стекла |
| Tier 2 | кирпич: глухие, `MaxHealth` 600 | стекло: `SeeThrough` + `ShootThrough`, `MaxHealth` 40 |
| Tier 3 | монолит (пулями не ломается) | бронестекло: только `SeeThrough`, неразрушимо |
| Tier 4 | монолит, гермодвери | стальные жалюзи (глухие, закрываются при тревоге) |

Мебель (`Furniture`) тоже с `MaxHealth`: стойка 150, плита 200, стол 80. Разрушенная
мебель получает `Broken` и останавливает ресторан; разрушенные стены и стекло
становятся проходимыми (`CanCollide`/`CanQuery` = false) до ремонта.

## 5. Охрана: кто кого атакует

В концепте есть противоречие. Раздел 3 говорит, что турели не видят
**только** разведчика с убранным оружием. Раздел 4 говорит, что вся охрана
игнорирует **любого** игрока с убранным оружием. Тогда маскировка разведчика
ничем не уникальна. Решение: правило обнаружения разное у людей и автоматики.

| Игрок на территории | Охранники (`Armed`) | Турели (`Intruder`) |
|---|---|---|
| Владелец | нет | нет |
| Чужой с оружием в руках | **да** | **да** |
| Чужой без оружия (Штурмовик, Подрывник, Танк) | нет («клиент») | **да** |
| Разведчик в маскировке | нет | нет |
| Разведчик взламывает кассу или раскрыт | **да** | **да** |
| В памяти тревоги (засветился, напал на ресторан) | **да** | **да** |

«Да» срабатывает только при трёх условиях: цель в радиусе, в секторе обзора
и в прямой видимости. Сектор не нужен, если по игроку уже поднята тревога.
Обнаружение поднимает тревогу на весь участок на 12 секунд; пока цель видна,
тревога продлевается. Целью выбирается игрок с наименьшим
«расстояние / Threat», поэтому Танк притягивает огонь.

Следствия для геймплея:

- Без оружия в зал может войти кто угодно, но на Tier 3+ турели встречают
  всех, кроме разведчика. Остальным классам нужен силовой штурм. Именно так
  и сформулировано в концепте.
- «Достал, выстрелил, убрал» не работает: игрок остаётся в памяти тревоги.
- Бронестекло: охрана видит стрелка за окном, но не стреляет сквозь стекло.
  Стрелок тоже не может стрелять внутрь.

## 6. Касса

1. Доход приходит раз в 2 с, пока ресторан работает (весь персонал жив,
   вся мебель цела). Касса заполняется до лимита уровня. Сумма видна всем
   через атрибут `Cash` на кассе: полная касса — приманка для рейдеров.
2. **Владелец** подходит и забирает выручку на кошелёк.
3. **Разведчик** в маскировке запускает взлом. Серверный таймер длится
   8–20 с в зависимости от уровня. Всё это время охрана, которая его видит,
   стреляет. Через 2 с владелец получает тревогу.
4. Взлом срывается, если вор погиб, отошёл от кассы, достал оружие, был
   раскрыт или его увидел владелец в радиусе 18 студов. В двух последних
   случаях маскировка слетает на 20 с.
5. Успех: вор забирает 75% кассы. Касса затем защищена 90 с, вор не может
   взламывать 30 с.

## 7. Классы: доработка концепции

**Проблема.** В исходной формулировке силовые классы только ломают. Им
нечего грабить, кроме денег убитого владельца, а различаются они лишь
характеристиками. Ниже — у каждого класса есть уникальное действие против
базы, а у громкого штурма появляется своя выгода.

| Класс | Роль в штурме | Уникальное | Слабость |
|---|---|---|---|
| **Штурмовик** | зачистка охраны | урон по охране ×1,5; «Подавление»: попадания на 3 с снижают точность охранника | слабый урон по стенам |
| **Подрывник** | пролом пути | урон по конструкциям ×3; пробивные заряды — единственный быстрый способ вскрыть гермодвери и жалюзи Tier 4; может разбить кассу | установка заряда 2 с, он уязвим |
| **Танк** | принимает огонь | 300 HP, Threat ×3 (охрана стреляет в него первой); разворачиваемый щит | медленный, мало урона |
| **Разведчик** | тихий грабёж и разведка | маскировка, взлом касс; метка, через которую пати видит охрану сквозь стены 10 с | 80 HP, раскрытие на 15–20 с |

**Громкий грабёж против тихого:**

- **Разбить кассу.** Это может любой класс (Подрывник — быстрее всех): у кассы
  есть запас прочности. Из разбитой кассы на пол высыпается 40% содержимого
  физическими пачками. Их нужно собрать под огнём, остальное сгорает.
- **Тихий взлом** даёт 75%, но требует времени, маскировки и выбора момента,
  когда охрана не смотрит.
- Итог: громко — быстро, но меньше и под огнём. Тихо — больше, но долго и
  рискованно. Оба пути укладываются в правило «деньги только в кассах».

**Связка рейда:** Танк забирает огонь турелей на себя. Подрывник вскрывает
стену сбоку от входа. Штурмовик зачищает охранников. Разведчик в суматохе
взламывает кассу. Каждый класс полезен, ни один не самодостаточен против
Tier 4.

**Против кого что работает:** люди-охранники — против вооружённых, турели —
против всех, кроме разведчика. Бронестекло — против снайперов, гермодвери —
против всех, кроме Подрывника. Против разведчика — сам владелец: поймать
его можно, только если стоять у кассы.

## 8. Анти-кемперство (без штрафов)

| Механика | Реализация |
|---|---|
| Нет денег на расстоянии | NPC-клиенты — визуальный слой: их убийство приносит $0 и **не** останавливает доход. Доход останавливается только из-за персонала и мебели внутри, а это требует штурма |
| Слепые зоны | Точки `CustomerSpawn` стоят под навесами у дверей; навесы — глухие детали без `SeeThrough` |
| Блик прицела | WeaponService на **сервере** добавляет яркий BillboardGui (`ScopeGlint`, поверх всего) на оружие с `Scoped = true`, пока оно в руках. Блик создан на сервере, поэтому его видят все, а клиент может убрать его только у себя |

## 9. Риски эксплойтов и как они закрыты

| Риск | Защита |
|---|---|
| Сбор или взлом кассы издалека (`fireproximityprompt`) | серверная проверка расстояния при запросе и всё время взлома |
| Мгновенный взлом (обход HoldDuration) | таймер взлома только на сервере |
| Чужой забирает выручку, не-разведчик взламывает | сервер проверяет роль; скрытие подсказок — только удобство |
| Флуд подсказками и Remotes | RateLimiter + очки подозрительности с киком |
| «Достал, выстрелил, убрал оружие» | память тревоги 12 с; раскрытие разведчика по времени |
| Спрятать оружие и стрелять | стреляет только оружие, экипированное на сервере (WeaponService) |
| Выстрел из другой точки или сквозь стену | начало луча — голова персонажа на сервере, клиент присылает только направление |
| Скорострельность выше положенной | темп и время доставания считает сервер по конфигу оружия |
| Подменить урон, дальность, разброс | всё берётся из `Config/Weapons` на сервере |
| Ломать свой ресторан ради чего-то | урон по своей мебели и охране не проходит |
| Аимбот (идеальное направление) | *не закрыт:* направление задаёт клиент; в планах статистика попаданий |
| Утащить охранника или повара физикой | `SetNetworkOwner(nil)` на всех NPC |
| Смена класса у чужой кассы | смена только на своей территории, кулдаун 30 с |
| Лечение сменой класса | при смене сохраняется доля здоровья |
| Бесплатный ремонт перезаходом | `NeedsRepair` сохраняется в данных |
| Мгновенный ремонт посреди штурма | ремонт и улучшение запрещены 20 с после боя |
| Двойное списание или зачисление пачкой запросов | проверка и запись без yield между ними |
| Выход из игры, чтобы спасти кассу | касса не сохраняется |
| Выход из игры, чтобы не терять кошелёк при смерти | выход в течение 15 с после урона = 20% кошелька остаются лежать на месте (CombatService) |
| Подобрать пачку денег издалека или дважды | сервер проверяет расстояние; пачка снимается и зачисляется без паузы между ними |
| «Фарм» убийствами со второго аккаунта | пачка — часть кошелька погибшего, деньги не создаются |
| Телепорт или спидхак к кассе | *в планах:* MovementService (позицию персонажа присылает клиент) |

## 10. Тестовая сцена

Тестовая карта описана в проекте и собирается вместе с кодом:

- `scene/Plots/Plot1…Plot4.model.json` — четыре участка (Origin, Territory, площадка, Spawn).
- `scene/Restaurants/Tier1…Tier4.model.json` — модели уровней из простых блоков:
  стены с атрибутами материалов, стойка, плита и столы (`Furniture`), касса
  (`CashRegister`), охранник-стрелок у входа (`Guard`, `Gunner`). На Tier 3–4 есть
  потолочные турели (`Turret`).
- `scene/Weapons/*.model.json` — пистолет, автомат, снайперская винтовка.
  Пистолет есть у всех, остальное выдаёт `/weapon`.
- `default.project.json` — земля и общая точка появления.

Тестовый охранник сделан без Humanoid, поэтому неуязвим. Этого хватает, чтобы
проверить обнаружение и стрельбу. Персонала (поваров с Humanoid) в тестовой
сцене нет. Настоящие модели заменят блоки позже: их сохраняют из Studio
в `.rbxmx` и подключают по тем же правилам.

CI собирает файл места после каждого пуша: **Actions → запуск → Artifacts →
`ro1-place`**. Шаг «Проверка сцены» (`tools/check_scene.py`) проверяет, что у каждого уровня
одна касса и есть мебель, у каждого защитника известный `DefenderType`, а у
участков есть `Origin` и `Territory`.

### Чат-команды (только в Studio)

| Команда | Что делает |
|---|---|
| `/help` | список команд |
| `/cash 50000` | добавить денег |
| `/upgrade` | улучшить ресторан |
| `/repair` | починить ресторан |
| `/class Stealth` | сменить класс (на своей территории) |
| `/weapon Sniper` | получить оружие (Pistol, Rifle, Sniper) |
| `/fill` | заполнить свою кассу |
| `/break` | сломать мебель — ресторан остановится |

Команды вызывают те же методы, что и Remote, со всеми проверками. В опубликованной
игре их нет: `DevCommandsService` создаёт их только при `RunService:IsStudio()`.

Для проверки охраны и взлома нужны два игрока: в Studio вкладка **Test →
Clients and Servers**, 2 игрока.
